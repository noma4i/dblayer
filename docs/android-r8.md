# Android R8 checks

The consumer rules preserve JNA's core package and generated classes used through reflection.
They preserve public fields and constructors of JNA structures, public callback methods, and native method names.
`RuntimeVisibleAnnotations` preserves `Structure.FieldOrder`.

```proguard
-dontwarn java.awt.**
-keep class com.sun.jna.* { *; }
-keepattributes RuntimeVisibleAnnotations
-keep class com.noma4i.dblayer.** extends com.sun.jna.Structure {
    public <fields>;
    public <init>(...);
}
-keep class com.noma4i.dblayer.** implements com.sun.jna.Callback {
    public <methods>;
}
-keepclassmembers class com.noma4i.dblayer.** {
    native <methods>;
}
```

UniFFI 0.32.2 generates `UniffiLib` and `IntegrityCheckingUniffiLib` objects using `Native.register`, rather than implementations of `Library`.
Native-declaring classes can be renamed because JNA receives `Class` objects. Their native method names remain unchanged.
Records, enums and errors use generated byte-buffer converters, without field-name lookup or reflective construction.
Their names can change. The check reads a record, verifies an enum, receives callback data, and catches a native error after optimization.
The JNA package rule follows its Android documentation: <https://github.com/java-native-access/jna/blob/master/www/FrequentlyAskedQuestions.md#jna-on-android>.

## Evidence

`kotlin/r8-check` compiles the real generated `dblayer.kt` and a small caller.
Its Android application enables release minification and consumes `kotlin/consumer-rules.pro`.
The JVM check runs R8-optimized class files against the host native library.
Both mappings must rename `Config`, which rejects a package-wide keep rule.

| Rules | Result |
| --- | --- |
| Previous package-wide rule | Native calls pass, then `Config is still pinned by a blanket keep rule` fails |
| Current rules | `R8 native calls, structures, callback, record, enum and error: passed` |
| Current rules | `R8 ordinary record obfuscation: passed`, Android `assembleRelease` succeeds |
| Remove public structure fields | `FieldOrder` names `[capacity, data, len]` do not match declared field names `[]` |
| Remove public structure constructors | `ForeignBytes$ByValue` has no public no-argument constructor |
| Remove callback rule | `Callback must implement a single public method` |
| Remove native-method rule | `UnsatisfiedLinkError`, renamed function `i` has no native symbol |

The mutations ran separately and the complete rules passed again afterward.
The JVM probe verifies calls through JNA. The Android check verifies DEX generation and mappings, without device execution.

| Minimal Android application | Previous rules | Current rules |
| --- | ---: | ---: |
| Uncompressed DEX bytes | 654640 | 371240 |
| DBlayer classes in mapping | 457 | 307 |
| APK bytes | 1260199 | 1178279 |

These sizes describe the check application. They do not predict another application's DEX reduction.
Kotlin 2.4.21, JNA 5.17.0, AGP 9.4.1, Gradle 9.8.1 and Android build tools 37.0.0 produced these results.
AGP reports a `Configuration.setVisible(boolean)` deprecation in Gradle 9.8.1.

## Reproduce

Run `bash scripts/build_kotlin.sh --host`, then `gradle -p kotlin/r8-check probe` through the build slot.
Set `ANDROID_HOME` to the Android SDK directory.
Use `-Dorg.gradle.jvmargs="-Xmx1g -XX:MaxMetaspaceSize=768m"` for the Gradle process.
Use `-Prules=/absolute/path/to/rules.pro` to check a modified rule file.
The full check includes the `gradle-r8` step after generating Kotlin bindings.
